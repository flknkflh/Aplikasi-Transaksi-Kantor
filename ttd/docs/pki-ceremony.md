# PKI ceremony (production — M7)

The lab CA is generated by `pqcsign-cli genpki` or `ca-admin init` without a
passphrase. **Production is different**: one witnessed run on an air-gapped
machine, encrypted keys, checksummed logs, split backups. A second run is only
needed on rotation or suspected compromise (Rencana V1 §13, §28, §29).

`tools/ca-admin` performs every mechanical step below. Reproducible fingerprints
and an append-only `ceremony.jsonl` (SHA-256 of every artifact + operator +
`ca_keys_encrypted`) make the run auditable.

---

## 0. Prerequisites

* Air-gapped machine, freshly imaged OS, no network cable / Wi-Fi disabled.
* Removable **encrypted** media for the CA directory + two labelled backup
  media kept in separate physical locations.
* Two witnesses. A printed run sheet with space for signatures + timestamps.
* Go 1.27 (to build `ca-admin`) **or** OpenSSL 3.5.x with ML-DSA:
  `openssl list -signature-algorithms | grep -i mldsa`.
* Entropy check: `cat /proc/sys/kernel/random/entropy_avail` (Linux) ≥ 256.

Generate a strong passphrase off-machine (e.g. 6+ diceware words), split it for
custody if policy requires, and never type it where it could be logged.

---

## 1. Generate the CA

```sh
export PQC_CA_PASSPHRASE='…the strong passphrase…'
export PQC_CA_OPERATOR='name@org'          # recorded in ceremony.jsonl

ca-admin init \
  --dir /mnt/ca-encrypted/pqc-ca \
  --root-cn "PQC PDF Root CA" \
  --inter-cn "PQC Device Signing CA"
```

Produces:

```
pqc-ca/
  root/key.pem.enc          root/cert.pem
  intermediate/key.pem.enc  intermediate/cert.pem
  public/  root-ca.crt.pem  intermediate-ca.crt.pem  ca-chain.pem
  ledger.json   ceremony.jsonl
```

* Root: ML-DSA-65, `CA:TRUE, pathlen:1`, `keyCertSign,cRLSign`, 10 y.
* Intermediate: ML-DSA-65, `CA:TRUE, pathlen:0`, `keyCertSign,cRLSign`, 5 y.
* Both private keys are AES-256-GCM under Argon2id(passphrase). `key.pem`
  (plaintext) is never written.

**Record on the run sheet:** the two fingerprints from `ca-admin status`, the
SHA-256 of `public/root-ca.crt.pem`, date/time, operator, both witness
signatures.

### OpenSSL equivalent (if not using ca-admin)

```sh
umask 077
openssl genpkey -algorithm ML-DSA-65 -aes-256-cbc -out root-ca.key.pem
openssl req -new -x509 -key root-ca.key.pem -days 3650 \
  -subj "/C=ID/O=ORG/OU=PQC Root CA/CN=PQC PDF Root CA" \
  -addext "basicConstraints=critical,CA:TRUE,pathlen:1" \
  -addext "keyUsage=critical,keyCertSign,cRLSign" \
  -addext "subjectKeyIdentifier=hash" \
  -out root-ca.crt.pem
sha256sum root-ca.crt.pem   # -> run sheet
```
Then an Intermediate CSR signed by the Root with
`basicConstraints=critical,CA:TRUE,pathlen:0`, `keyUsage=critical,keyCertSign,cRLSign`.

---

## 2. Back up

```sh
ca-admin backup --dir /mnt/ca-encrypted/pqc-ca --out /mnt/backup-A/pqc-ca.tar.gz
# repeat onto /mnt/backup-B
sha256sum /mnt/backup-*/pqc-ca.tar.gz   # -> run sheet, must match
```

Keys inside the archive stay encrypted. Store the two media in separate safes.
Rehearse recovery before going live:

```sh
ca-admin restore --in /mnt/backup-A/pqc-ca.tar.gz --dir /tmp/restore-drill
ca-admin status  --dir /tmp/restore-drill      # gate OK, fingerprints match §1
rm -rf /tmp/restore-drill
```

---

## 3. Distribute — public material ONLY

Copy to the deployment host / repo:

```
public/root-ca.crt.pem        <- pinned into every client + the server config
public/intermediate-ca.crt.pem
public/ca-chain.pem
public/crl.pem                <- after step 5
```

**Never** copy `root/`, `intermediate/`, `key.pem.enc`, `ledger.json`,
`ceremony.jsonl`, or a backup archive to any online system. `ca-admin status`
runs the M7 gate (`public/` contains no private-key material) and fails if it
does.

---

## 4. Issue device certificates (per enrolment batch)

The receiver exports approved CSRs; the operator carries them to the CA
machine, issues, and carries the certificates back.

```sh
# on the server (online):
#   for each approved enrolment id:
#   curl -H "Authorization: Bearer $ADMIN" \
#     $API/api/v1/admin/enrollments/$id/export > /media/in/$id.csr.pem
#   echo '{"account":"…","device":"…","cn":"…"}' > /media/in/$id.meta.json

# on the CA machine (offline):
ca-admin batch-issue --dir /mnt/ca-encrypted/pqc-ca \
  --in /media/in --out /media/out --days 365 \
  --crl-url https://verify.example.id/api/v1/public/ca/crl.pem

# back on the server:
#   for each /media/out/*.crt.pem :
#   curl -X POST -H "Authorization: Bearer $ADMIN" \
#     --data-binary @cert.pem $API/api/v1/admin/enrollments/$id/certificate
```

Identity comes from `--cn` / `.meta.json`, **never** from the CSR subject
(§13.5). Each issuance appends to `issued.jsonl` and `ceremony.jsonl`.

---

## 5. Revocation and CRL

```sh
ca-admin revoke --dir /mnt/ca-encrypted/pqc-ca \
  --serial <hex> --reason keyCompromise      # or superseded, cessationOfOperation, …
ca-admin crl --dir /mnt/ca-encrypted/pqc-ca  # -> public/crl.pem, CRL number bumped
```

Publish `public/crl.pem` to `/api/v1/public/ca/crl.pem` (or
`POST /api/v1/admin/crl/import`) and restart / signal the API. Re-issue the CRL
on a schedule (e.g. weekly) even with no new revocations so `nextUpdate` stays
fresh; clients warn on a stale CRL.

---

## 6. Rotation / compromise

* **Intermediate compromise:** revoke the Intermediate at the Root, issue a new
  Intermediate, re-issue device certs from it, publish a CRL, redeploy the new
  `ca-chain.pem`. Devices keep their keys; only certificates change.
* **Root compromise:** full re-ceremony (§1) + new client builds pinned to the
  new Root + re-enrol every device (§28 step 9). Old signatures verify only
  against the old Root.
* **Scheduled rotation:** overlap — issue the new Intermediate before the old
  one expires; ship a `ca-chain.pem` containing both during the transition.

---

## 7. Sign-off

The run is complete when the run sheet has, for every step: timestamp,
operator, both witness signatures, and the recorded fingerprints/checksums.
File the sheet with the backup media custody log.
